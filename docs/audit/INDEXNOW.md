# B05 — IndexNow deployment boundary

## Scope and payload

**B18 (19. 9. 2026):** automatic notifications send **only URLs that may have changed** since the previous verified production run (see `scripts/indexnow-changed.mjs`): baseline = `head_sha` of the last successful `indexnow-after-deploy` run on main; `git diff --name-only` maps `src/content/clanky/<slug>.md` → `/clanky/<slug>/` + `/` + `/clanky/` + `/temata/<category>/`, `src/data/videos.json` → `/`, static `src/pages/*.astro` → their route; templates/components/CSS/scripts/workflows/docs → nothing. Candidates are intersected with the validated production sitemap, so a URL not published is never sent. No previous production run or baseline not an ancestor of the deployed SHA → STOP with zero POST (never the whole site). Empty selection → zero POST, job succeeds. Manual CLI and `notifyDeployment` without `zmenene` keep the previous full-sitemap semantics. Previously: the entire validated production `sitemap-0.xml`. Existing semantics are preserved; batches contain at most 10,000 URLs in sitemap order. The public verification key is unchanged. `/indexnow-deployment.json` is a new machine asset, not a page, navigation entry, sitemap entry or notification URL. No source facts, existing URLs, HTML, DNS, dashboard settings, secrets or configured environment variables are changed.

The existing `npm run build` command now invokes `scripts/indexnow-marker.mjs` after Astro finishes its sitemap. It reads the **existing platform-injected** `CF_PAGES=1`, `CF_PAGES_BRANCH`, `CF_PAGES_COMMIT_SHA`, and `CF_PAGES_URL`; it does not set them. Valid metadata creates a versioned marker with branch, full SHA, exact allowlisted deployment origin and SHA-256 of sitemap bytes. Git HEAD is cross-checked when available. All-absent local metadata removes any stale marker and emits none; partial/invalid metadata fails the build after removing the stale marker. An honest preview may generate its preview branch, never a fabricated main identity.

The deployment hostname is parsed from the authenticated Cloudflare check link and compared to platform metadata. Only HTTPS, eight-hex immutable host form under `realtech-web.pages.dev`, no credentials/port/path/query/fragment (optional root slash) is accepted. **No UUID-prefix derivation.** Unknown link formats, aliases or ambiguous multiple links fail closed. Parent must verify the real preview metadata agrees before release; do not relax the comparison to make it pass.

## Bounds, failure and caching

- At most 30 polling passes, 20-second pauses, and an absolute **10-minute evidence deadline** checked before each read and POST. Reads already in progress have a 10-second timeout. The workflow's outer timeout is 20 minutes. A failed validation may stop earlier rather than retry unsafe evidence.
- If the new build is not verified on production within the bound, the script exits **nonzero**, the workflow **FAILS**, and there are **ZERO IndexNow POSTs**. No success fallback, cleanup deployment, deployment mutation, or alternate-origin notification. A cancellation also cannot authorize an unverified POST.
- API/bootstrap bodies capped at 1 MiB; markers 4 KiB; sitemap 5 MiB. Streaming byte checks apply even without Content-Length. Evidence GETs forbid redirects, use fresh nonconditional no-cache/no-store requests and unique query values. Existing checks reject Age other than zero, missing/old Date (60-second window), Warning or a non-revalidating cache policy. `CF-Cache-Status` is not required or used as an authorization gate: Pages may omit it. No replacement mandatory header is introduced. Nonces do not prove origin freshness.
- POSTs have a 15-second timeout, forbid redirects and accept only HTTP **200 or 202**. Never log response bodies, tokens or environment. A successful response is submission acceptance, **not proof of search indexing**. There is no automatic POST retry after ambiguous failure. Earlier accepted batches cannot be undone if a later batch fails; the final checks still stop subsequent batches.
- Concurrency cancellation limits overlapping jobs, not exactly-once delivery. A valid rerun for the same still-current deployment can resubmit the full sitemap.

This is corroborated provenance, not a signed platform attestation. It trusts reviewed main source, the existing Cloudflare control plane/build metadata and production domain/TLS. Authorized operators can override CF variables; a compromised host can lie. CDN revalidation assumptions and the final GET→POST race remain: deployment and IndexNow cannot be made atomic. No zero-race/global-freshness guarantee is claimed.
