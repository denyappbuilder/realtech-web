## Findings and fixes

| Severity | Finding / evidence | Resolution |
| --- | --- | --- |
| Medium | `src/components/SearchModal.astro`: focus trap includes `a[href]` results despite their `tabindex=-1`. Real Chrome, query Astra: Tab from input → close → scrollable results → background logo while dialog remains open. | Filter candidates by sequential `tabIndex >= 0`. Chrome after fix alternates input/close; no escape to background. |
| Low | `SearchModal.astro`: HTTP-200 non-array JSON or malformed rows are cached, making subsequent searches throw and preventing retry until reload. Reproduced with `{error: ...}`, `[null]`, and a null title. This is fault injection, not an observed production incident. | Validate required string fields and array shape before caching. Reuse existing failure status and retry path. Empty valid arrays remain valid. |
| Low | `SearchModal.astro`: old keyboard target survives until the asynchronous refresh when reopening an empty search. | Clear current results synchronously together with the input. An invariant regression test covers the pre-await state; no claim of an observed normal browser navigation race. |
| Low | `scripts/test-indexnow-cli-prepinace.mjs`: baseline test fails on macOS because imported script resolves `/var` → `/private/var` but its read spy compares the unresolved fixture path. | Canonicalize temporary fixture root using `realpathSync`. No production IndexNow code or network submissions changed. |

## Security/config/dependency assessment

- Public `https://realtech.cz/` returned 200 and live CSP, HSTS, nosniff,
  DENY framing, referrer and Permissions-Policy headers matching `public/_headers`.
- Site is statically generated (`astro.config.mjs`, no SSR adapter). The sole
  Pages Function canonicalizes two exact production alias hosts; preview hosts
  intentionally continue without redirect. No user-supplied server rendering,
  database, upload endpoint, or image-optimization server was identified.
- `npm audit --json` baseline: **9 affected package groups: 1 critical,
  7 high, 1 low**. These are dependency advisory severities, not confirmed
  remotely exploitable production findings. Astro is critical; sharp,
  fast-xml-parser, js-yaml, nanoid, postcss, smol-toml, svgo are high;
  esbuild is low. Registry recommendations include Astro 7, a major upgrade.
- Static deployment greatly reduces SSR/dev-server attack paths. It does not
  remove build-time risk from untrusted Markdown, YAML, XML, images or plugins,
  nor compiler-output XSS risk. Do not run dev servers publicly or build
  untrusted contributions with privileged secrets. Exploitability was not
  penetration-tested; patch-level dependency follow-up is separate.
- Existing dependency PRs were discovered, not overwritten/closed/merged:
  #395 js-yaml, #396 nanoid, #397 postcss, #398 svgo, #400 fast-xml-parser,
  #409 sharp, #438 smol-toml; Astro major work #401/#429 remains separate.
- CSP still permits inline scripts/styles; replacing this requires a designed
  hash/nonce strategy and third-party embed testing, not a blanket removal.
- Six existing IndexNow TODO cases remain (XML entities/whitespace, absolute
  URL handling and valid short/hyphenated keys). Current website canonical
  paths are clean; no production IndexNow operation was run.
